# FreeUnit: параллельные потоки работ (5 + 3 дня)

Принципы:
- У каждого потока свой git worktree и своя ветка `claude/<stream>`. Слияние идёт в рабочую ветку через PR размером 70–150 строк.
- Одновременно активны не больше 3–4 потоков. Ограничения: один ревьюер и лимиты Max 5x.
- Для файлов, которые трогают сразу несколько потоков, заранее назначен владелец и порядок слияния (раздел 3).
- Любой PR проходит гейты G1–G6 из основного плана.

Модели:
- **H** — Haiku;
- **S** — Sonnet;
- **F** — Fable;
- **O** — Opus;
- **—** — без LLM, работает скрипт.

## 4. Как это запускать (оркестрация)

- Один поток — это один субагент или одна сессия с worktree (`isolation: worktree`) и своей карточкой потока (этот файл, раздел 1).
- Opus оркестрирует: раздаёт задачи из таблиц, принимает результаты по гейтам и держит порядок слияния из раздела 3.
- Лимиты: одновременно не больше 1 агента уровня O или F. Потоки на S и H работают параллельно.
- Состояние всех задач хранится в `build/fidx/experiment.jsonl` и в чек-листе.
