# FreeUnit: отчёт о работе D1–D4 (сентябрь 2026)

Рабочая ветка: `freeunitorg/freeunit`, `claude/freeunit-c-vulnerabilities-perf-mvssit`.

Прототипы и планы вынесены в `andypost/unit`: там черновые PR `proto/*` и `plans/reports`.

Все исправления сделаны по одному правилу:
1. Сначала пишется воспроизводящий тест.
2. Тест должен падать без исправления и проходить с ним.
3. Гейты G1–G6: сборка с `--hardening=strict` под gcc и clang, C-тесты, ASan+UBSan, ast-grep по базовой линии, дизассемблер горячих функций, раскладка структур в общей памяти.

## Код и безопасность (router ↔ app — граница доверия)

| Что | Итог |
|---|---|
| Чтение mmap-записей (router и libunit) | Неполный хвост читался за пределами буфера. `nxt_unit_mmap_at` переполнялся при id `0xFFFFFFFF` и падал с SEGV. Исправлено через `nxt_span`. |
| `nxt_router_prepare_msg` | Имя заголовка длиной 251–255 байт плюс `HTTP_` обнуляло `uint8_t`; метод вообще не ограничивался. Теперь на такое имя возвращается 431, на такой метод — 501. |
| #394, фрагменты | Лимиты по числу потоков и объёму на порт. |
| #425 | Падение в release-сборке и assert в debug. Обе сборки теперь ведут себя одинаково. |
| #422 | Таймаут рвал WebSocket после upgrade. Теперь таймаут снимается в момент upgrade. |
| #429, #430, #435 | Лимиты кадров WebSocket в ASGI и Java, причина закрытия в Java. |
| #431 | Объектная форма `compressors` роняла router при валидации. |
| #172, cookie | Гипотеза опровергнута. Найдена другая проблема: приложение может испортить состояние nncq и навсегда подвесить поток router (D4, в работе). |
| Фаззер `fuzz_unit_msg` | 44.7 млн прогонов, падений нет. |
| Инструменты | `--hardening`, `nxt_checked.h`, `nxt_span.h`, 8 правил ast-grep по базовой линии, `run_gates.sh`, CI-проверка «нельзя менять код без теста». |

## `schedules` (cron для Drupal)

- Верхнеуровневая секция `schedules`: запросы идут через слот протокола DEVNULL, на worker engine.
- Параметры: `overlap: skip` / `queue`, таймаут, состояние сохраняется при переконфигурации.
- Счётчики доступны в `/status`.
- Тесты: 118 (Python и PHP), чисто под ASan.
- Документация: `docs/schedules.md`, OpenAPI, ADR-0004.
- `fastcgi_finish_request()` скрывает от `overlap: skip` работу, которая продолжается после отправки ответа. Это задокументировано.

## Производительность

- Микробенчмарк очередей, проверка дизассемблера горячих функций, проверка раскладки структур через `pahole`.
- Поля `nxt_port_s` переставлены: 456 → 448 байт, горячие поля занимают 3 кеш-линии. Замер A/B дал разницу в пределах шума.
- В контейнере нет доступа к аппаратным счётчикам CPU (PMU), поэтому для настоящих замеров нужна другая машина.
- Выбор инструментов:
  - CI использует `objdump` плюс `pahole`, эталон — clang 18 на glibc.
  - `llvm-mca` — только для анализа разработчиком.
  - Раскладка структур под musl и glibc на x86_64 совпадает.

## Наблюдаемость

- 8 USDT-проб. Без `--usdt` они ничего не стоят; это проверено по дизассемблеру.
- `traceparent` доходит до PHP.
- Приложение получает `parent-id` спана FreeUnit, поэтому спаны Drupal вкладываются в спан FreeUnit.
- `/status/schedules`.

## Исследования (черновые PR в andypost/unit)

- **h2/h3 (ADR-0005).**
  - h2 — через nghttp2.
  - h3 — через ngtcp2 + nghttp3 за опцией `--h3`, при OpenSSL 3.5 и новее. Запасной вариант — quiche.
  - Оба прототипа запускались на epoll.
- **Модуль Drupal `freeunit`.** Функции по убыванию ценности:
  1. раздельные приложения FreeUnit для админки и фронта;
  2. cron через `schedules`;
  3. перезапуск после деплоя через control API;
  4. статический кеш страниц в router: 103 тыс. запросов в секунду против 19 тыс. у PHP.
  - Найдены пробелы в FreeUnit, F1–F7. F1 исправлен.
- **DDEV-аддон `ddev-freeunit`.** Работает через `webserver_type: generic` и `web_extra_daemons`. Сборка PHP embed из sury работает без патчей.

## Замер моделей (фабрика кода)

- Итог по двум прогонам:
  - Haiku: принято 4 из 12;
  - Sonnet: 10 из 12;
  - Fable: 4 из 4.
  - Ни одна модель не «исправила» заведомо корректный код в задачах-ловушках.
- Главный вывод: качество тестового стенда влияет на результат сильнее, чем выбор модели.
- Распределение работы:

  | Уровень | Кто делает |
  |---|---|
  | L1 | ast-grep без LLM, затем Haiku |
  | L2–L3 | Sonnet |
  | L4 и ревью | Fable |
